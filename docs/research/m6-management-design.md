# M6 경영 시스템 구현 설계

상태: 독립 설계. M4 수동 수용 및 M5 구현/수용 전 게임에 연결하지 않는다.
관련 #107, #74, #73, #35, #72, #32. 원작 수치가 아닌 초기 실험안이다.

## 경제와 저장 경계

모든 금액은 정수 센트다. 설비 지출은 재료 purchases/cost와 분리한
`capitalExpenses`, 직원/광고는 `wages`/`advertising`으로 기록한다.
현금 변화 = 매출 − 공급 구매 − 임대 − 이동 − 설비 − 급여 − 광고.
일일 영업 이익은 재료 원가/임대/이동/급여/광고를 차감하고 설비는 별도 표시한다.
기존 장부에 비용을 소급하지 않는다. M5 v3 확정 뒤 다음 저장 버전을 정한다.
카탈로그 ID와 효과는 OPEN snapshot에 고정하고 복구 replay에서 재청구하지 않는다.

## 최소 두 선택의 실험 카탈로그

| 시스템 | 선택 | 초기 비용/효과 | 전략과 검증 |
| --- | --- | --- | --- |
| 설비 | 냉장고 | 1800센트, NEXT DAY 얼음 50% 보존(내림) | 얼음 구매가 큰 날 유리, 설비 없는 기존 녹음 그대로 |
| 설비 | 제빙기 | 3200센트, NEXT DAY 60개 공급 | 남은 얼음은 기존처럼 녹고 새 공급, 재고 999 초과 방지 |
| 직원 | 보조 판매원 | 일 150센트, 서비스 8→6틱 | 혼잡도 낮으면 급여 손해 |
| 직원 | 숙련 판매원 | 일 300센트, 서비스 8→4틱 | 도심 줄 포기 감소, 기본 수요가 적으면 손해 |
| 광고 | 동네 전단 | 일 100센트, 유입 10% 증가 | 저비용, 날씨/장소 기본 유입에 곱함 |
| 광고 | 지역 광고 | 일 250센트, 유입 25% 증가 | 공급/서비스 부족 시 추가 유입만 낭비 |

무직원/무광고도 유효 선택이다. 동시에 직원 한 명과 광고 한 종류만 활성화한다.
설비는 한 번만 구매, preparation에서 현금 부족 시 상태와 비용 변경 없음.
냉장고/제빙기는 함께 보유 가능하되 보존→새 공급→999 상한 순서를 명시한다.
직원 고용/해고와 광고 예약은 preparation에서만, OPEN에서 하루 비용 확정.
미지급 급여를 부채로 숨기지 않고 현금 부족하면 OPEN 거부·해제 선택 제공.

## 화면과 검증 분할

고전 녹색 패널의 Upgrades/Staff/Marketing를 실제 동작과 함께 추가한다.
Price를 Marketing에 옮기며 가격 범위/키보드 조절을 보존한다.
Results/Rent/Upgrades/Staff/Marketing/Recipe/Supplies 일곱 탭은 기능 완성 후만 표시한다.
효과/오늘 비용/현재와 예약을 구분하고 구매·해고 확인을 제공한다.

1. 비용 순수 함수와 설비·고용·광고 atomicity, 중복 구매/재클릭/부족 현금 검사.
2. 구형 결과 비용 0 migration, 알 수 없는 ID와 모순된 snapshot 거부.
3. 준비 UI와 OPEN 연결, 가격 입력·좁은 화면·키보드 회귀.
4. 30일 여러 seed/장소에서 무투자와 각 투자 수익·대기 포기·파산률 비교.
5. 비용 결제 뒤 종료/replay, 다음 날 녹음/보존/공급, import와 Windows 복구 검사.

투자가 항상 이기거나 불리하면 숫자를 수정하고 비교 원자료를 기록한다.
구매력/유입 증가를 추가 매출로 직접 지급하지 않는다. 결정적 방문자와 실제 판매가 회계의 근거다.
