조사일: 2026-09-29. 목표는 **원작처럼 보이고 조작되는 두 번째 MVP**다. 초록색 테마 변경만으로 완료하지 않는다. 이번 조사에서는 스크린샷 12장을 직접 열어 확인하고, PC판 FAQ를 교차 확인했다. 원작 실행이나 동영상 재생을 완료한 조사는 아니다.

## 1. 먼저 고정해야 할 판본

**시각 기준은 Softpedia의 Windows 영어판 스크린샷 묶음**으로 정한다. 메뉴에 Version 1.1.5가 보이며 준비부터 결과까지 같은 UI를 비교할 수 있다. 해당 페이지의 갱신 날짜를 게임 출시일로 해석하지 않는다. 실행 파일의 빌드나 Deluxe 명칭과의 관계는 검증하지 않았다.

다른 자료에는 `advertising / price`가 별도 탭인 화면이 있고, 기준 묶음에는 `staff / marketing`이 있다. 이 차이를 한 화면에 섞지 않는다. 모바일판, Lemonade Tycoon 2, 동명의 최근 게임은 기준에서 제외한다. [기준 메뉴 R01](https://games-cdn.softpedia.com/screenshots/Lemonade-Tycoon_1.jpg), [다른 탭 구성 R12](https://gamefabrique.com/screenshots2/pc/lemonade-tycoon-03.big.jpg).

## 3. 화면을 수치로 비교

기준 이미지에서 Windows 제목줄을 제외하면 약 640×480이다. 아래는 이미지 경계를 수동으로 읽은 **대략적인 좌표**이며 ±3~5px 오차가 있다. 정확한 원본 UI 좌표를 추출했다는 뜻은 아니다.

| 영역 | 원작 기준 좌표 / 크기 | 설계에 미치는 영향 |
| --- | --- | --- |
| 재고·현금 | x≈4, y≈0, w≈632, h≈28 | 그림+숫자를 한 줄에 놓고 현금은 오른쪽 끝 |
| 왼쪽 아이콘 탭 | x≈7, y≈62, w≈310, h≈49 | 현재처럼 패널 안에 큰 바로가기 3개를 넣지 않음 |
| 오른쪽 예보·뉴스 | x≈326, y≈34, w≈310, h≈78 | 전체 폭의 DAY/CASH/WEATHER 대시보드를 없앰 |
| 왼쪽 작업 패널 | x≈7, y≈120, w≈310, h≈289 | 선택한 탭 하나의 작업만 표시 |
| 오른쪽 동네 | x≈331, y≈124, w≈300, h≈240 | 약 5:4 장면; 게임 전체 면적의 약 23% |
| 장소 소개/평가 | 장면 바로 아래, 오른쪽 패널 안 | 장소 이름·소개·인기/만족도에 안정적인 자리 제공 |
| 하단 행동 | 왼쪽 패널 아래 | 시작 버튼이 화면 전환마다 멀리 이동하지 않음 |

관찰 근거: R02/R06/R08/R09. M2에서는 640×480을 **배치 설계 기준**으로 쓰되 브라우저 글자를 강제로 작게 축소하지 않는다. 960×720 정도의 데스크톱 표시에서도 같은 상대 비율을 유지하는 것이 제안이다.

현재 구현을 1280×1000 브라우저에서 측정한 값: 앱 1056×905.7, 본문 폭 1040, 왼쪽 360, 오른쪽 673, 장면 669×459.9. 현재 좌우 비중은 약 35:65이고 장면 비율은 약 1.45:1이다. 원작의 거의 50:50 / 1.25:1과 차이가 크다. 이것이 색을 바꿔도 원작처럼 느껴지지 않는 주요 원인이라는 **분석**이다.

## 4. 화면별 조작 계약

### 준비

- 원작에서 직접 보이는 것: 고정된 아이콘 탭, 왼쪽 단일 작업 패널, 계속 보이는 재고·예보·동네. 레시피의 재료 그림과 숫자 조작이 크다. R06.
- 재료 화면은 재료 선택 → 묶음별 수량 편집 → BUY/CANCEL 구조를 보여준다. 클릭 전후의 실제 재고 차감 시점은 정지 화면만으로 확정하지 않는다. R07.
- **M2 구현 계약**: BUY 전에는 구매 초안만 바꾸고, BUY는 합계 검증 후 전부 반영, CANCEL은 원상복구한다. 이는 스크린샷에서 읽은 패턴을 바탕으로 우리가 명확히 정하는 동작이다.
- 탭을 바꿔도 수정 중인 값이 사라지지 않고, 잘못된 값이 있으면 해당 탭으로 돌아가 설명한다. 전체 레시피/가격/재료 폼을 동시에 펼치지 않는다.

### 영업

- R08은 왼쪽에 실적과 오늘 설정을 동시에 보여준다. 준비 탭은 흐려지고, 오른쪽 장면과 장소 소개의 위치는 그대로다.
- **M2 구현 계약**: 재고·금액은 거래 때 갱신, 준비 편집은 잠금, 구매/거절/품절은 구분되는 반응으로 표현한다. 속도 버튼은 장면 가까이에 둔다.
- 원작 손님의 보행 프레임 수, 정확한 대기 시간, 줄 정렬과 판매 간격은 미확인이다. M1의 순차 고객 처리 속도를 원작 수치라고 부르지 않는다.

### 결과 / 다음 날

- R09는 금액뿐 아니라 만족도, 놓친 판매, 손실 사유를 함께 보여준다. R02는 전날 결과와 다른 장부 화면이다.
- **M2 구현 계약**: 전날 결과와 누적 장부를 구분하는 실동작 하위 탭을 만들고, 지출·이익·현금 증감을 혼동시키지 않는다. 미구현 비용을 계산하는 척하지 않는다.
- 준비로 돌아와도 원작의 화면 틀이 유지되어야 한다. 결과가 긴 웹 보고서처럼 늘어나는 것을 피한다.

## 5. 아트 / UI 제작 명세

아래 수치는 관찰 기반의 **제작 목표**다. 원본 에셋을 추출한 수치가 아니다.

| 항목 | 관찰 | M2 목표 |
| --- | --- | --- |
| 공간 | 앞·옆 벽과 지붕, 대각선 길, 화면 밖으로 잘린 건물 | 하나의 약 2:1 바닥 투영을 도로/집/소품/동선에 공유 |
| 장면 크기 | 작은 사각 창 안의 촘촘한 동네 | 우측 5:4 장면, 주택가 1곳을 먼저 완성 |
| 카트 | 큰 고정 가게보다 작은 파라솔 노점 | 장면 폭의 대략 7~10%; 현재 카트 11.25%에서 재검토 |
| 손님 | 좁고 길쭉한 실루엣, 작은 머리와 분리된 다리 | 장면 높이의 대략 6~10%; 가판대와 겹쳐도 방향이 구분됨 |
| 선 / 질감 | 가는 어두운 외곽선, 적은 면별 명암, 미세한 잔디 | 두꺼운 블록 윤곽과 넓은 단색 빈 땅을 줄임 |
| 색 | 밝고 강한 초록 패널, 더 어두운 재고 바, 라임 조작부 | 현재의 다소 어두운 녹색 조합을 원작과 나란히 조정 |
| 글자 | 제목·숫자는 세로로 긴 형태, 본문은 작은 선명한 글자 | 장식적인 이탤릭 로고를 줄이고 글자 폭/행간/대비를 우선 맞춤; 정확한 폰트는 미확인 |
| 버튼 | 작은 그림 탭, 밝은 윗변·어두운 아랫변, 큰 좌우 화살표 | 활성/눌림/잠김 상태를 각각 제작, 라운드 카드와 넓은 여백 금지 |
| 자원 아이콘 | 레몬·설탕·얼음·컵이 색과 형태로 구분 | 설탕이 단순 상자로 보이는 현재 아이콘을 재제작 |

R11의 주택가, R03/R08의 공원, R10의 역을 함께 비교했다. 장소 수를 늘리는 것이 이번 M2 목표는 아니다. 환경 밀도·비율의 참고로 사용한다. 아이콘과 스프라이트는 원작을 참고해 새로 제작하며 참조 이미지는 런타임 에셋으로 쓰지 않는다.

## 6. 현재 구현과의 차이 / 우선순위

| 우선순위 | 차이 | 해야 할 일 |
| --- | --- | --- |
| P0 | 좌우 35:65, 큰 풍경과 별도 대시보드 | 50:50 화면 틀, 상단 재고/현금, 오른쪽 예보·뉴스 |
| P0 | 바로가기 버튼 + 긴 전체 폼 | 실제 전환형 준비 탭, 같은 위치의 행동 버튼 |
| P0 | 즉시 구매 | 구매 초안/확정/취소, 재고·잔액 검증 |
| P0 | 레시피는 컵 단위인데 원작은 피처 표시 | M2에서는 컵 단위를 명확히 유지; 숫자만 원작처럼 바꿔 의미를 속이지 않음 |
| P0 | 영업 중 왼쪽 큰 빈 공간 | 실적 + 오늘 설정 두 패널 |
| P0 | 한 장짜리 결과 | 전날 결과/누적 장부, 고객 반응 영역 |
| P1 | 현재 장면 640×440, 큰 카트와 반복 집 형태 | 5:4 구도, 카트 축소, 건물 실루엣·소품·동선 재배치 |
| P1 | 글자·아이콘·베벨이 임의 스타일 | 공통 UI 그림/색/타입 규격과 비교 캡처 |
| 후속 | 저장, 확장 장소, 직원·광고·업그레이드 경제 | M2에 전부 끌어오지 않음; 기존 이슈 유지 |

원작의 7개 탭 모두를 넣으면 직원/임대/업그레이드 기능까지 필요해진다. **M2에는 동작하는 Results, Price, Recipe, Supplies 중심으로 만들고, 위치 정보는 우측에서 제공**한다. 미구현 탭을 작동하는 것처럼 꾸미지 않는다. 기준 판본의 Marketing 대신 Price를 사용하는 것은 광고 미구현에 따른 명시적인 차이로 남긴다. 원작과 완전히 동일한 기능 수를 요구하는 마일스톤은 아니다.

## 7. 미확인 사항과 후속 검증

- [PC 플레이 영상 후보 A](https://www.youtube.com/watch?v=Ra_V8qP2Jzw), [롱플레이 후보 B](https://www.youtube.com/watch?v=IdnO6ntYAgs)를 찾았지만 이번 환경에서 재생·장면 검증에 성공하지 못했다. 타임스탬프, 보행 속도, 소리, 전환 시간은 측정하지 않았다.
- 기준 1.1.5 묶음의 Marketing 화면은 직접 확보하지 못했다. R12의 광고 화면을 그 자리에 대신 넣지 않는다.
- 정확한 폰트/팔레트/애니메이션 프레임은 아직 모른다. JPEG의 한 픽셀 값을 원본 팔레트로 확정하지 않는다.
- 피처 생산·얼음 손실·대기열 경제를 M1과 동일하다고 보지 않는다. UI만 먼저 가까워지는 동안 현재 규칙의 명칭과 결과를 유지한다.
- 고객 표현 작업 시작 전에 영상 또는 실제 실행으로 확인할 체크리스트: 입장 방향, 가판대 앞 회전, 기다림/판매/음용 자세, 말풍선 의미, 겹침 순서, 퇴장, 배속/종료 전환. 확인되지 않으면 원작 동작 재현 완료라고 표시하지 않는다.

## 8. M2 완료 판정

1. 준비(레시피/가격/재료), 영업, 결과를 **같은 크기의 원작 캡처와 나란히** 비교한다.
2. 좌우 폭 차이가 5%p 이내이고, 재고/예보/탭/장면/설명의 상대 위치가 원작 기준과 맞는다. 장면은 약 5:4, 전체 데스크톱 구성은 4:3에 가깝게 유지한다. 이는 우리의 검수 허용치다.
3. 하위 화면은 실제로 전환되고 BUY/CANCEL, 입력 보존, 영업 잠금, 결과/다음 날이 동작한다.
4. 고객 그래픽·반응·동선이 구분되고, 원작에서 직접 확인한 것과 독자 구현한 동작이 리뷰에 표시된다.
5. 3일 연속 플레이, 무판매/품절/잔액 부족/취소/재시작과 375px 배치, 타입·린트·빌드·브라우저 검증을 통과한다.
6. 사용자에게 동일 크기 비교 자료를 제시하고 **원작에 충분히 가까워졌다는 시각 검수**를 받은 뒤 M2를 완료 처리한다. CI 통과만으로 디자인 완료를 선언하지 않는다.

이 문서는 조사 산출물이며 M2 구현 완료 보고가 아니다.
