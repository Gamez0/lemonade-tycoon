# 원작 지향 경제·장비 역할 계획 — #285

## 결정

확인된 묶음 가격은 #284/PR291에서 구매 원가와 함께 복원한다. 임대료·임금·장비
가격을 한꺼번에 원작 숫자로 바꾸지는 않는다. 현재 손님 수·서비스·장비 역할이
원작과 다르므로 같은 숫자만 적용하면 경제 전체의 유사도를 보장하지 못한다.
다음 구현은 가격 규칙의 버전 분리와 취득 원가 보존, 확인된 화면 정보 차이 개선이다.
원작 계수가 필요한 역할 변경은 필요한 관측을 명시한 조사 게이트로 남긴다.

이는 게임 전체 개선을 중단하는 결정이 아니다. 독립적으로 실행 가능한 작업과
원작 실행 환경이 필요한 관측을 아래에서 구분한다. 원작 자산을 배포하지 않고,
만료된 체험판을 다시 실행하지 않는다.

## 현재 규칙으로 한 가격 교체 실험

`scripts/economy-price-study.cjs`와 [결과 JSON](original-economy-study.json)은
실제 원작 관측이 아닌 **현행 리메이크의 반사실 실험**이다. 12개 시드, 첫날,
레시피 6/3/2, 장비·광고 없음, 충분한 구매 재고, 인위적인 현금·장소 해금으로
조건을 고정했다. 각 조건에서 25센트 간격의 $0.25–$5 가격 중 평균 이익이 가장
큰 값을 고른다. 원작 임대료와 임금만 교체하고 나머지 계수는 그대로 두었다.
총 14,400일을 계산했으나 실제 연속 플레이나 사람 테스트가 아니다.

| 장소, 직원 없음 | 현행 가격의 평균 영업이익 | 원작 가격만 적용한 평균 영업이익 |
| --- | ---: | ---: |
| Neighborhood | $23.81 | $23.81 |
| Park | $24.84 | $16.84 |
| Downtown | $37.93 | $12.93 |
| Beach | $33.42 | $1.42 |
| Old Square | $48.92 | -$31.08 |
| Train Station | $43.75 | $19.75 |
| Mall | $33.49 | -$6.51 |

같은 Park 조건에서 원작 임금을 적용한 서버는 -$42.35, 호스트는 -$62.40이었다.
이는 모든 레시피·장비·광고·평판·날짜를 최적화한 결과가 아니다. 원작의 실제 수익,
최고 수익, 전역적인 불가능성을 뜻하지 않는다. 현행 고객·시간 계수에 가격만
대입하는 구현을 정당화할 근거가 부족하다는 구체적인 경고다. 결과에 맞추려고
손님 수나 가격 허용치를 임의로 늘리지 않는다.

재현: 잠금 파일로 의존성을 설치한 뒤 `npm test`,
`node scripts/economy-price-study.cjs docs/reviews/original-economy-study.json`.
시드와 모델 소스 해시가 JSON에 들어 있다. 스크립트의 가격 교체는 별도 Node
프로세스 안에서만 일어나며 소스·게임 저장·배포 파일을 수정하지 않는다.

## 경제와 진행의 도입 순서

1. 현재 회사는 $40 시작 자금과 기존 경제 규칙을 유지한다. 새 묶음 원가는 별도
   버전으로 도입한다. 기본 준비 구매는 레몬 40/$3.20, 설탕 20/$0.80,
   얼음 50/$1, 컵 75/$1로 총 $6이며 무료 Neighborhood에서 첫 영업이 가능하다.
2. 전역 가격을 바꾸기 전에 회사별 경제 규칙 식별자와 불변 가격표를 마련한다.
   가격표에서 현재 장비의 역할을 원작 역할과 구분하고 취득 원가를 저장한다.
3. 향후 원작 가격 규칙은 새 회사에서만 선택·도입한다. 기존 회사에 중간 날짜부터
   자동 적용하지 않는다. 원작 시작 자금이 미확인인 동안 임의의 지원금·재고 증여로
   비싼 임대료를 상쇄하지 않는다.
4. 성장 순서는 무료 장소의 재고·레시피 학습 → 묶음 할인과 재고 관리 → 유료 장소의
   예상 비용과 손실 위험 이해 → 근거 있는 장비 역할과 가판대 구매가 되도록 한다.
   $49.99 주서기를 초반 목표로 쓰려면 실제 리필 단계와 가속 근거가 먼저 있어야
   한다. 효과 없는 이름뿐인 장비를 추가하지 않는다.
5. 원작 임대료·임금·장비 가격 채택 전, 여러 날·시드·장소·레시피·가격·장비 조합으로
   현금 생존, 직원의 추가 매출, 장비 회수 기간, 유료 장소의 의미를 검토한다.
   목표 달성이나 해금 조건도 같은 경제 규칙으로 버전 관리한다. 위의 하루 실험을
   그 검토의 완료로 간주하지 않는다.

## 저장·장부 호환 계약

- schema13의 묶음 원가 모델과 미래의 전체 경제 규칙은 별개의 식별자다.
  v6–v12 지급 완료 개점과 과거 기록은 기존 모델로 계속 재생한다.
- 미래 `economyRules` 식별자는 새 회사의 개설 시 결정한다. 이전 문서는 현행
  고정 가격표에 매핑하고, 읽는 동작만으로 현금·재고·장비 가치를 바꾸지 않는다.
- 장비 자산 가치는 취득 당시 가격을 합산한다. 현재 `balanceSheet`와 저장 검사의
  장비 원가가 전역 `UPGRADES.prices`를 다시 참조하므로 먼저 분리해야 한다.
  소유한 장비에 다음 구매 가격을 적용하거나 자동 보상금을 지급하지 않는다.
- 개점에 동결된 임대료·이동비·임금·광고비는 지급 시 금액을 보존한다. 현재 저장
  검사가 임금·광고비를 전역 표와 비교하는 부분도 규칙별 가격표로 바꿔야 한다.
- 과거 영업이익, 현금 증감, 취득 원가, 무료 얼음, 재고 가치는 서로 구분한다.
  물가 변경은 과거 기록의 정산식을 다시 계산할 이유가 아니다.
- 새 규칙의 저장 파일은 이전 앱이 안전하게 거절해야 한다. 최신 원본을 오래된
  백업으로 조용히 덮어쓰지 않는 현재 보호를 유지한다.
