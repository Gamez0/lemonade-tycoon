# 음악 개선 조사·제작 계획 — v2 / 2026-11-02

사용자 우선순위에 따라 #113의 음악 제작 작업을 재개한다. 앞선 경제/UI 후속 #283–285는 Ready로 보존하며 이번 작업과 섞지 않는다. 기존 효과음과 오디오 설정·포커스 복귀 기능은 유지할 기반이다.

## 현재 상태와 확인 범위

현재 준비 음악은 64스텝×0.48초=30.72초, 영업 음악은 64×0.3초=19.2초다. 단선율을 삼각파로 재생하며 화성 반주·베이스·드럼 파트가 없다. 정산은 16×0.48초=7.68초 패턴을 반복한다. 고정 0.32초 발음이라 영업의 0.3초 간격에서는 일부 음이 겹칠 수 있다. 이는 소스에서 확인한 구성이고, 청취 피로도 평가와는 다르다.

기존 원작 오디오 조사 #236은 21레코드/17고유 데이터의 코덱·채널·속도를 확정하지 못했다. 단순 PCM 후보를 원작 음악으로 간주하지 않는다. 공개 자료에서는 동명의 2025년 Taupe 앨범과 게임 2편을 구분해야 한다. 2002년 게임의 공개 longplay를 참고 경로로 확보했으나, 이번 도구로 실제 소리를 검증해 장르·BPM·악기 구성을 확정하지는 못했다. 따라서 아래 음악 방향은 **창작 제안**이며 원작 음악 분석 결과라는 주장을 하지 않는다. 기존 legacy `bgm.mp3`도 출처·사용 권한을 확인하지 않고 채택하지 않는다.

## 제작 방향과 작은 비교 시안

두 시안은 같은 프로젝트용 새 선율·화성 재료를 사용하고, 비슷한 청감 음량으로 비교한다. 원작 선율이나 녹음을 가져오지 않는다.

| 방향 | 편성·리듬 | 목적 |
| --- | --- | --- |
| A: Porch Ensemble | 따뜻한 피아노, 나일론 기타, 낮은 반주, 절제된 타악기. 느슨한 스윙 | 준비 화면에서도 오래 두기 편한 작은 동네 분위기 |
| B: Sunny Counter | 기타 리듬을 앞세우고 비브라폰 응답, 같은 주제의 가벼운 직선 리듬 | 영업의 활기와 효과음 가독성 비교 |

각 시안은 32마디 약 1분 이상으로 만들고 A–A변주–B–A회귀의 구성을 갖춘다. 4마디짜리 짧은 선율만 계속 반복하지 않는다. 정산은 동일한 음악 어휘의 짧은 종지 시안으로 제작한다. 기존 단선율 기준본도 함께 렌더링해 비교할 수 있게 한다. 초기 게임 후보에는 A를 준비, B를 영업에 대응시켜 각각 64마디로 확장했다. 정산은 4.8초 일회성 큐다. 최종 선택과 원작 유사도 판정은 청취 확인 후 결정한다.

## 제작 방식과 출처

- 새 악보·편곡·이벤트 데이터·MIDI를 프로젝트 소스로 남긴다.
- 피아노/나일론 기타: Meta Open Sound의 CC0 악기 샘플. 저장소 커밋, 파일 URL, 바이트 수, SHA256, 라이선스를 고정한다.
- 비브라폰/타악기: VCSL의 CC0 샘플. 같은 방식으로 출처를 고정한다.
- 원본 악기 샘플은 필요한 부분만 내려받아 제작용으로 보관한다. 전체 음원 은행을 게임 실행 시 로딩할 필요는 없다.
- GeneralUser GS도 조사했으나 샘플 출처 불확실성을 밝힌 저자 설명이 있어 이번 시안의 기본 재료로 고르지 않았다.
- Runway 음악 생성 도구를 탐색했으나 연결되지 않았다. 연결·결제·크레딧 사용을 전제하지 않고 현재 제작 가능한 악기 기반 시안을 진행한다.

## 단계와 완료 산출물

1. **조사·방향:** 현재 곡/재생 구조, 원작 근거의 한계, 도구와 출처, 이 문서. 진행 중 #113에 기록.
2. **비교 가능한 시안:** A/B, 정산 큐, 기존 기준본. WAV 마스터, 게임용 OGG, 악보/MIDI, 출처 목록, 루프와 음량 측정. 로컬 청취 페이지에서 동일 음량 비교와 게임 화면 맥락을 제공.
3. **선택한 방향의 본편 편곡:** 현재 후보를 바탕으로 사용자 청취 의견과 원작 기준을 확인한 후 다듬는다. 정산 큐는 필요 이상 반복하지 않고 동작을 명시.
4. **게임 통합:** 사전 렌더 파일의 단일 음악 버스, 짧은 크로스페이드와 효과음 분리. 속도/SKIP이 재생 속도·피치를 바꾸지 않음. 포커스·숨김·음소거·오디오 장치 중단에서 중복 소스 없이 복귀. 로드 실패 시 게임은 계속 진행.
5. **검증·인수:** 아래 기술 검사와 실제 게임 흐름을 확인하고 소스·마스터·게임용 파일·크레딧·라이선스를 묶는다. 사람 청취·20분 피로도·최종 음악 수용은 #113에서 별도로 확인한다.

## 검증 기준

- 기준본/A/B의 전체 음량을 측정해 비교 가능한 범위로 맞춘다. 시안 목표는 약 -21 LUFS, true peak -2 dBTP 이하이며 값만으로 음악적 완성을 판정하지 않는다.
- 루프는 마지막 음의 잔향을 잘라내거나 긴 무음으로 숨기지 않는다. 끝→처음 3회 연결본과 경계 파형/차분을 확인한다. OGG 디코딩 후에도 길이·경계를 검사한다.
- 악기·파트별 휴지, 음역, 강약, 마디별 변화, 효과음과의 경쟁을 청취 항목으로 남긴다.
- 각 전환, 1배/4배/SKIP, 음량0/음소거, 숨김/포커스 복귀, 장치 중단·복귀, 파일 실패를 브라우저와 실제 Windows 패키지에서 확인한다.
- 현재 자동 검사는 오실레이터 생성 횟수를 보고 있어 파일 재생으로 바꿀 때는 실제 음악 소스의 시작·중단·복귀·중복을 보는 검사로 갱신해야 한다. 기존 보호를 조용히 삭제하지 않는다.
- 오프라인 실행, 음악 추가에 따른 패키지/디코딩 메모리 증가, 기존 256MiB private 메모리 한도를 확인한다. 일반 게임 저장·장부 규칙은 변경할 이유가 없다.

## 사용자 방향 확인

사용자는 “원작과 비슷한 분위기와 악기 질감이 우선”이라고 답했다. 따라서 단순히 더 자연스러운 새 음악이라는 이유만으로 현재 후보를 최종 채택하지 않는다. 원작 음악의 실제 단서를 추가 조사하고, 확인된 악기 질감·리듬·배경에서의 비중을 기준으로 후보를 평가한다. 아직 확인되지 않은 장르·템포를 원작 특징으로 쓰지 않는다.

현재 렌더는 Meta의 공개 OGG 악기 샘플과 VCSL WAV를 쓴 시안이다. 24-bit WAV 출력이라고 해서 모든 악기 원본이 무손실이라는 뜻은 아니다. 방향 확인 후 최종 마스터에 전체 품질 WAV 적용을 검토한다. 파일별 원본 포맷은 sample-sources.json에 남긴다.
## 재생 방식 검증 결과 — 2026-11-03 KST

HTML 오디오 반복은 실제 Chromium 출력 녹음에서 약 66ms 공백이 검출되어 채택하지 않았다. 현재 후보는 4마디 단위의 무손실 FLAC 33개(총 14,396,123바이트)를 사용한다. 재생 중인 구간과 다음 구간만 디코딩하고 AudioBufferSource를 오디오 시계에 맞춰 예약한다. 전환 시 최대 300ms 크로스페이드하고, 음소거/포커스 이탈 시 노드와 버퍼를 해제한다. 음악 시간은 게임 4배속과 분리한다.

실제 MusicPlayer 출력을 MediaRecorder로 녹음하고 런타임 FLAC를 이어 디코딩한 PCM과 상관 분석했다. 준비/영업 각각 구간 경계와 전체 반복 경계를 검사하여 오차는 0~0.023ms, 상관계수는 0.998 이상이었다. 시간 위치를 경계 직전으로 옮긴 기술 검사이며 실제 플레이 기록이나 사람 청취 판정을 대신하지 않는다. 실패했던 HTML 방식의 측정도 로컬 증거로 보존한다.

Windows 패키지의 실제 오디오 중단·복귀·음소거 검사 통과. 메모리 한도 256MiB를 유지한 성능 검사에서 최대 구간 평균 private 메모리 240.973MiB, 유휴 화면 canvas 갱신 0회를 확인했다. 이는 구간별 평균이며 순간 최고 사용량을 뜻하지 않는다. 장시간 실제 기기 청취·20분 피로도·원작 질감 유사도는 아직 미확인이다.

재현 방법은 ../README.md를 참조한다. WAV 청취 내보내기는 런타임 FLAC 구간을 직접 이어 디코딩한다. OGG는 청취 페이지용이며 Windows 게임의 재생 파일과 구분한다.
